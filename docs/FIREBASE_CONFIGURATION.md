# Firebase Configuration

How Firebase (used for push notifications via FCM) is wired into both the Flutter frontend and the Laravel backend, and exactly what a new developer needs to set up locally. Firebase project: `fintechwallet-bbaca` (see `frontend/firebase.json`).

---

## Frontend

| File | What it is | Committed to git? |
|---|---|---|
| `frontend/firebase.json` | FlutterFire CLI's own config — records the Firebase project ID and the app ID for each platform (`android`, `ios`, `macos`, `web`, `windows`). Regenerated by running `flutterfire configure`. | Yes |
| `frontend/lib/firebase_options.dart` | Generated Dart file with each platform's `FirebaseOptions` (API key, app ID, project ID, etc.) baked in as constants. This is what `Firebase.initializeApp()` actually reads at runtime via `DefaultFirebaseOptions.currentPlatform`. | Yes |
| `frontend/android/app/google-services.json` | Android's native Firebase config file, downloaded from the Firebase console. | Yes (present) |
| `frontend/ios/Runner/GoogleService-Info.plist` | iOS's native Firebase config file, downloaded from the Firebase console. | **Missing — see Open Items below.** |

**Why both `firebase_options.dart` and the native per-platform files exist:** `firebase_options.dart` is what FlutterFire's Dart-side `Firebase.initializeApp()` call uses directly, so Firebase *core* initialization works on every platform `firebase.json` lists (including iOS) purely from this one generated file. The native files (`google-services.json`, `GoogleService-Info.plist`) are separately required by each platform's native build tooling and by some Firebase SDK features that read platform-native config directly rather than through the Dart layer.

**Which platforms actually support push notifications:** `PushNotificationService.isSupportedPlatform` explicitly checks for this — `firebase_messaging` ships no plugin implementation for Windows or Linux at all (only Android, iOS, macOS, and web), regardless of what `firebase_options.dart` configures for those other platforms.

### Setting up a new local frontend environment
1. Get added to the `fintechwallet-bbaca` Firebase project in the Firebase console (or point `firebase.json`/`firebase_options.dart` at your own project if this is a fresh setup — see FlutterFire's own docs for `flutterfire configure`).
2. `google-services.json` is already committed — no action needed for Android.
3. **iOS: download `GoogleService-Info.plist` from the Firebase console yourself and add it to `frontend/ios/Runner/` in Xcode** (drag into the `Runner` target, "Copy items if needed" checked) — this file does not exist in the repo yet (see Open Items).

## Backend

| Setting | Value | Where |
|---|---|---|
| `FIREBASE_CREDENTIALS` | Path to the Firebase service-account JSON key. Defaults to `storage_path('app/firebase/service-account.json')` if unset. | `.env` / `.env.example` (present but empty — the default path applies), wired in `config/services.php` as `services.firebase.credentials` |
| Service account file | A Google Cloud service-account key JSON, downloaded from the Firebase console (Project Settings → Service Accounts → Generate new private key). | `backend/storage/app/firebase/service-account.json` (gitignored — never commit this file; it's a real credential) |
| OAuth scope requested | `https://www.googleapis.com/auth/firebase.messaging` | `PushNotificationService::SCOPE` |

**How the backend uses it:** `AppServiceProvider::register()` builds a singleton `PushNotificationService`, constructing a `Google\Auth\Credentials\ServiceAccountCredentials` from the file at `services.firebase.credentials`. If that file is missing, unreadable, or invalid, the exception is caught, logged as a warning (`"Push notifications disabled: ..."`), and the service is constructed with **null** credentials instead of failing app boot. Every method on `PushNotificationService` treats null credentials as "push disabled" and silently no-ops — a missing or broken Firebase setup degrades push notifications, it does not break the app.

### Setting up a new local backend environment
1. In the Firebase console for `fintechwallet-bbaca` (or your own project): Project Settings → Service Accounts → Generate new private key.
2. Save the downloaded JSON to `backend/storage/app/firebase/service-account.json` (create the `firebase/` directory if it doesn't exist — it's gitignored, so a fresh clone won't have it).
3. Leave `FIREBASE_CREDENTIALS` unset in `.env` to use that default path, or set it to a different absolute path if you keep the key elsewhere.
4. No credential is needed to run the app or its test suite without push working — this is a deliberate no-op-when-unconfigured design, not a hard requirement.

## Open items

- **iOS `GoogleService-Info.plist` is missing from the repo.** Confirmed still absent as of this doc (2026-09-30). Dart-side Firebase *core* initialization on iOS would still work from `firebase_options.dart` alone, but full push delivery to a real iOS device also needs APNs keys/certificates registered in the Apple Developer portal and linked in the Firebase console — none of that has been verified. This is exactly why NOV-34 ("Verify iOS push end-to-end") exists as its own separate, currently-blocked task rather than being assumed to work.
